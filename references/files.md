# 议题文件与 harness 分工

## 职责

- **harness** 管工作区导航：识别或新建 project、命名、定位入口、维护整体文件夹索引。它可以是已有 AGENTS.md 规则、运行时项目上下文或项目管理工具，不要求另装服务。
- **本 skill** 管当前议题：读取必要上下文，边讨论边直接写 Markdown，更新项目内的成果和当前进度。
- **文件工具** 完成普通的读、写、编辑。没有独立“保存助手”，不要求 Python、专用命令、自动快照或版本数据库。

同一 AI 可以先按 harness 规则定位 project，再按 skill 工作。这是职责划分，不需要另起一个 agent。已有 harness 的项目目录、命名和索引约定优先，不能再建第二份总索引。

## 一个议题，一个 project

开始时先使用 harness 已指定的 project。没有指定时，只查它的项目索引和用户明确提供的目录；同一议题继续用原目录，不能每次调用模块、换对话或隔天继续就再建一个项目。

新主题、新的独立沟通事项或新的独立复盘周期，才考虑新建。改措辞、补证据、调整听众或路线通常属于同一议题的迭代。确实无法判断是否是新议题时问一句，不仅凭几个相似关键词合并。

没有现成命名规则时，harness 采用：

- project 目录：`YYYYMMDD-简短议题`，日期是首次创建日期，按用户时区；主题通常 4–20 个字，能说明讨论什么。例如 `20261023-客服积压原因分析`。
- 名称只含中文、字母、数字和连字符；去除换行及路径分隔符，避开系统保留名。不能把用户给的字符串直接当文件路径。
- 不使用“新项目”“最终版”“PPT1”这类无法识别议题的名称；不放个人敏感信息。
- 同议题已经存在就复用；确为不同议题但名称撞车时优先加具体范围，仍重复再加 `-02`、`-03`，不覆盖已有目录。
- 名称创建后保持稳定；第二天继续不用改日期，修改目标不自动改名。确需改名由 harness 同步索引和引用。

项目根目录优先沿用宿主工作区已有约定。若工作区没有现成约定，默认在工作区 `projects/` 下建立议题目录，并用 [议题项目索引模板](../assets/projects-index.md) 维护 `projects/INDEX.md`。若用户已指定具体文件夹，就在该文件夹内直接写内容；若连位置都未指定且无法建默认目录，只问要存到哪个文件夹。不要在已有工作区总索引之外另建第二套全局注册表。

## project 内部

以下路径相对于本议题的 project，不是 skill 安装目录。只创建当前需要的文档，不铺满空目录和模板。

```text
20261023-客服积压原因分析/
  当前进度.md
  skills/INDEX.md       用户挂载额外 skill 时才生成，仅管本议题的方法
  00-准备/本次汇报.md
  01-盘素材/素材与判断.md
    原始材料/          保留原件，按需接收
    摘录/              按需保存必要摘录和来源
    计算/              有必要计算时才生成
  02-叙事/叙事选择.md
  03-写作/逐页大纲.md
    讲稿.md            需要时生成
  04-评审/评审意见.md
    修改说明.md        需要时生成
  05-交接/交接说明.md  交接时生成
  归档/                仅保存重要定稿或大改前的稿件
```

阶段编号只为文件排序，不要求依次执行。各模块用固定名称便于继续编辑；同一份成果的小改写回同一文件，不每天生成新文档。素材可用 `M01-工单统计-20261016至20261022.csv`，编号稳定，原件可保留原名并在素材判断中登记。必要的衍生摘录用 `M01-关键数据摘录.md`。

只有正式交付、重要分支或覆盖重要稿件时才另存，如 `归档/逐页大纲-20261023-交付稿.md`；同名已存在时加序号。不要默认每轮递增版本号、生成哈希或自动备份。已有版本标识可继续使用，没有时以文件路径、更新时间和对应章节标明依据。

## 什么时候写 Markdown

形成一项有用内容就直接写，不等最后完成整份 PPT：

- 确定了部分背景或目标，写本次汇报，未知项保留未知。
- 读出关键材料，写素材判断及必要摘录，注明来源位置。
- 提出了候选路线或用户作出选择，写叙事选择。
- 写了几页、评审意见或改稿，更新对应成果。
- 用户回答关键问题，立即将有效答案写回成果，更新当前未决项。

纯帮助、没有新信息的讨论不产生无意义文件。已有内容只做局部更新，原始材料不改写，用户编辑过的段落先读再改。写入后做一次轻量读回，确认本轮内容与路径正确；回复给出实际文件链接。

若写入失败，明确哪些内容未写入，给待保存文本；不能说已保存。内容成功、进度失败时分别说明，下次先对账。未改动的文件不必重复读写。

## 当前进度只管本议题

`当前进度.md` 是本议题的续接入口，不是项目总目录或另一个待办系统。它只需回答：

- 本议题是什么、当前正在处理什么。
- 已有哪些成果（相对链接），哪些结论由用户明确选择，哪些仍是暂定。
- 当前最关键的未决问题、用户已回答的内容或跳过原因。
- 下一次从哪里继续；如有变更，哪些现有成果需复核。

首次使用引导完成可简记一次，避免重复教程。只把用户明确拍板的结论记为“已确认”，AI 的建议不算用户已确认；给完评审意见也不代表原稿已定稿。信息较多时再用表格。

整体 project 列表、其他议题目录、全局文件树都不写在这里。内容变化也不要求改 harness 总索引；只有新建、路径变化或入口变化等导航变化才交给 harness 处理。

若本议题有临时 skill，当前进度可链接 `skills/INDEX.md`，不要重复抄技能表。技能索引只列本项目采用的额外方法；它不是整体文件夹索引。加载与停用见 [外部 skill 规则](skills.md)。

## 变更与继续

`/继续` 先由 harness 定位 project，再读当前进度、当前成果及必要依据；只复核受变化影响的内容。

- 目标／听众／使用方式变：复核素材相关性、叙事、页面、讲稿和已有评审。
- 证据口径变：沿 M 编号检查引用它的路线和页面。
- 页面变：复核对应讲稿、评审及已交接内容。

文件中的内容比旧进度更可靠；有冲突就记录具体差异，不用最近修改时间推断用户已确认。不要因为“需复核”清空成果或重新开始全部流程。

## 交接

在本项目内写 `05-交接/交接说明.md`，说明汇报人、听众、目标、场合、关键限制、相对文件清单、未决问题和接收者下一步。再次调用 `/交接` 时直接更新同一份说明；只在用户需要可移动副本时再建立 `05-交接/交接包-YYYYMMDD/`，保留原相对结构，避免递归复制整个 project。

已有讲稿和实际引用的必要材料一起带上；无法复制的材料标明缺口。检查相对链接。副本是交接时的内容，不承诺之后自动同步；上游变化时更新说明或另建新的交接副本。

新对话续接本地内容不一定要打包，给 project 路径即可。整体项目索引仍由 harness 管。任何打包都不等于已经获准对外发送。
