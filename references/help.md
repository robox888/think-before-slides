# 使用场景

> 给助手：用户说 `/帮助`、“怎么用”“有什么功能”时读本文件。先列「五个常见场景」的标题和开口示例，问哪个最接近；用户选了再展开该场景。用户问某个口令（如 `/帮助 评审`）时，只讲工具一览里那一行和相关场景。任务进行中被问到时，按当前进度推荐最相关的一个场景。不要整篇贴出。

以下人物和数字都是虚构的。口令不用记，直接说话效果一样；也没有固定顺序，从哪个场景开始都行。

## 五个常见场景

| 场景 | 可以这样开口 |
|---|---|
| 1. 只有题目，不知道讲什么 | 「下周要给运营总监讲客服积压，我还没想好讲什么。」 |
| 2. 材料一堆，不知道哪些能用 | 「材料在这个文件夹，帮我看看能说明什么。」 |
| 3. 知道要讲什么，想排顺序写成稿 | 「先说结论再讲依据，写成三页。」 |
| 4. 已经有稿，想挑毛病再改 | 「先别改，看看这份稿有没有硬伤。」 |
| 5. 要上台讲，或交给别人接手 | 「上台怎么说？」「整理一下，交给同事做页面。」 |

### 场景 1：只有题目，不知道讲什么

适合领导让你“讲一讲”，但材料和想法都还散着。

> **你：** 下周要给运营总监讲客服积压，我还没想好讲什么。
>
> **助手：** 先定一件事：听完以后，你希望总监知道什么，或者定下什么？
>
> **你：** 让他知道积压在涨，但原因还没查清，先别急着加人。
>
> **助手：** 好，这次是对齐现状和证据缺口，不谈加人。已写进 `00-准备/本次汇报.md`。接下来看看你手上有哪些数据？

助手一次只问一个问题。答不上来可以说“你先给个建议”。

**得到：** `00-准备/本次汇报.md`（谁讲给谁听、想要什么回应、自己看还是现场讲），以及记录做到哪一步的 `当前进度.md`。

**再用一次：** 情况变了就再说。比如“总监说这次顺便定要不要加人”，助手会改目标，并告诉你之前写好的哪几页要重看。

### 场景 2：材料一堆，不知道哪些能用

> **你：** 材料就两个数：上周末未结 80 单，这周末 120 单。有人说是系统故障，但没有工单明细。
>
> **助手：** 多了 40 单，涨了 50%。这能说明积压在涨；是不是系统故障，现在还判断不了，要看同期的进线量、处理量和故障时段。这两条我记成了 M01、M02。

每份材料编一个号（M01、M02……），写清它能说明什么、还说明不了什么。数字用工具复算。

**得到：** `01-盘素材/素材与判断.md`，必要时附摘录和计算过程。

**再用一次：** 补到新材料就再说一次，比如“我拿到了工单明细”。新材料接着编 M03，原有编号不变；新材料推翻了之前的判断时，助手会标出哪些页面受影响。

### 场景 3：知道要讲什么，想排顺序写成稿

> **你：** 先说结论再讲依据，写成三页，别写得像在要资源。
>
> **助手：** 好，按“积压变化 → 原因还不能确定 → 下一步补什么”写三页。

每页写标题、副标题、核心观点和支撑说法。第 1 页大致是：

- **标题：** 本周末未结工单 120 单，比上周末多 40 单（+50%）
- **副标题：** 两个时点统计口径相同，原因尚未查明
- **核心观点：** 先对齐积压在涨这件事，原因放到下一页
- **支撑说法：** M01。只有两个时点，看不出进线和处理各自变了多少；数字由用户提供，原始记录未核对

拿不准顺序时，助手会给一两种讲法，说清各自适合什么情况，你选一个再写。

**得到：** `02-叙事/叙事选择.md`、`03-写作/逐页大纲.md`。

**再用一次：** 说“换个顺序，先讲影响”，会新增一条路线，原路线留着，随时能换回去；“第 2 页展开一点”只改第 2 页；“压到两页”会重新分页，整份重写前先把旧稿存档。

### 场景 4：已经有稿，想挑毛病再改

现成稿不用先走前面的步骤，直接给稿就行。

> **你：** 先别改，看看这份稿有没有硬伤。
>
> **助手：** 最要紧的一条：第 2 页标题写“系统故障导致积压上升”，但材料里只有一句转述，没有故障记录，总监会以为原因已经查明。建议改成“系统故障是待验证的原因之一”。另外两条在评审意见里。
>
> **你：** 按第 1、3 条改，第 2 条等补了数据再说。

意见落到具体页码和原句，说清问题和后果，一般先挑最要紧的三条。你没选的不改。

**得到：** `04-评审/评审意见.md`；改稿后原稿更新，`04-评审/修改说明.md` 记下改了什么、哪些没改。

**再用一次：** 改完再评一轮，新一轮写在同一份意见里，标明第几轮、上轮的问题解决了没有。也可以换个角度评，比如“假设总监只有三分钟，再看一遍”。

### 场景 5：要上台讲，或交给别人接手

> **你：** 上台怎么说？大概十分钟。
>
> **助手：** 按现有三页写了讲稿，每页有开场、过渡和要点。

> **你：** 整理一下，交给同事做页面。
>
> **助手：** 交接说明写好了：目标、听众、三页内容在哪、哪些数字还没核实、他下一步做什么。

隔天回来，说“接着昨天的积压分析”并给出文件夹位置，助手会先读进度，问过的问题不再问。

**得到：** `03-写作/讲稿.md`、`05-交接/交接说明.md`。

**再用一次：** 页面改了，说“更新讲稿”就会同步；交接说明随进展更新。整理好的材料只存在本地，发不发给别人由你决定。

## 工具一览

每个工具都能随时用、反复用。再用时在原文件上更新，不另起一份。

| 口令 | 做什么 | 直接说也行 | 写到哪 | 再用一次 |
|---|---|---|---|---|
| `/开始` | 开一个新汇报，或说清卡在哪 | 「有点乱，不知道从哪弄」 | `当前进度.md` | 同一个汇报沿用原文件夹 |
| `/准备` | 理清谁讲给谁听、想要什么回应 | 「我该围绕什么讲？」 | `00-准备/本次汇报.md` | 更新目标，指出要重看的内容 |
| `/素材` | 看材料能说明什么 | 「这些数有用吗？」 | `01-盘素材/素材与判断.md` | 新材料接着编号，判断变了会标出来 |
| `/叙事` | 排讲述顺序 | 「讲不顺，换个顺序」 | `02-叙事/叙事选择.md` | 新路线追加，旧路线保留 |
| `/写作` | 写逐页稿 | 「按这个写成几页」 | `03-写作/逐页大纲.md` | 只改点名的页；整份重写前存档 |
| `/评审` | 挑问题，不动原稿 | 「先别改，看看硬伤」 | `04-评审/评审意见.md` | 按轮次记录，对照上一轮 |
| `/改稿` | 按选定的意见改 | 「按第 1、3 条改」 | 原稿、`04-评审/修改说明.md` | 只改指定范围，修改说明累加 |
| `/讲稿` | 写上台怎么说 | 「上台怎么说？」 | `03-写作/讲稿.md` | 页面改了再用一次就同步 |
| `/交接` | 整理给别人接手 | 「交给同事做页面」 | `05-交接/交接说明.md` | 更新同一份说明 |
| `/进度` | 看做到哪、还缺什么 | 「做到哪了？」 | 读 `当前进度.md` | 随时看 |
| `/继续` | 接着上次做 | 「接着上次」 | 当前步骤的文件 | 随时接 |
| `/技能` `/挂载` `/停用` | 查看、借用、停用你自己的 skill | 「用我这个写作 skill 改第 3 页」 | `skills/INDEX.md` | 随时挂上或停用，原文件不动 |
| `/帮助` | 看这些场景 | 「怎么用？」「/帮助 评审」 | — | — |

口令后面可以带要求，比如 `/评审 只看第 2–4 页`、`/改稿 第 3 页说得直接点`。

## 借用自己的 skill

有好用的写作、研究或审稿 skill，可以在这次汇报里借用：

> 把「我的写作 skill 路径」挂到这个汇报，用于改稿。只改表达，不改事实和结论。

| 你怎么说 | 效果 |
|---|---|
| 「这个汇报改稿都用它」 | 这个汇报里一直用，换对话也记得 |
| 「只这一次改标题时用」 | 用完就停 |
| 「这次别用，下次还用」 | 本次跳过 |
| 「以后不用它了」 | 停用，原文件留着 |

只在当前汇报里生效，不会带到别的汇报，也不会装到全局。
