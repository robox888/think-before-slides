# 写作：让每页承担一件事

读本次汇报、素材判断及选定路线。已有稿件直接承接用户要求的范围；不要求补一套形式性的前序文档。当前核心主张或路线仍互斥时先问；缺证据但用户要求试写时，可做标明缺口的草稿。

直接写入 project 内的 `03-写作/逐页大纲.md`，文件头注明输入文件（已有版本号则沿用，否则用更新时间与对应章节）、使用方式、页数安排理由以及仍未核实的部分。按实际时长、信息量和阅读方式分配页数，不强凑封面、收尾或固定十页。

每页四项：

```markdown
## 第 1 页
- 标题：本页要点或判断。
- 副标题：必要范围或背景；无必要时写“不设”。
- 核心观点：希望对方理解的一件事。
- 支撑说法：依据、解释、关键限制及 M 编号和原文位置；建议注明“建议”。
```

一个叙事部分可跨页，也可合并多个相关部分。四项不重复同一句话。关键事实、限制必须在页面可见，不能藏在讲稿里。

自行阅读的内容要包含必要背景、定义、推理和承接。现场讲解可压缩页面文字，用户需要讲稿时写入 `03-写作/讲稿.md`，按页对应并注明采用的大纲文件及版本或更新时间，写过渡和解释，不新增无依据事实。再次调用 `/讲稿` 时，对照最新逐页大纲同步更新对应页的讲稿，保留未改动页的口播细节。用户要求 `/讲稿` 已是生成授权；若本来是自行阅读，简短说明此次增加的是讲解用途。

交出本轮稿前检查：目标是否一致、主张是否有支撑、数字口径是否正确、相邻页是否重复、关键限制是否遗漏。能修的直接修，不再增加自查审批。未核实部分明示，不称为可直接正式发布的完整稿。

局部修改只动相关页面。再次调用要求整份重写或重新分页时，先把现稿另存到 `归档/`，再写回 `03-写作/逐页大纲.md`。牵涉目标、主张或路线变化时，写清受影响内容，不静默推翻整稿。大纲变化后同步受影响的讲稿；不能同步时标需复核。
